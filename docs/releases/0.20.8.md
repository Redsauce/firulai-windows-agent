# Windows 0.20.8 (publicacion activa bloqueada por permisos RSM)

- Version objetivo seleccionada desde RSM (propiedad 1990), con descarga de la
  release concreta y comprobacion de firma, version, destino, hash y tamano.
- Consulta inmediata al arrancar, cada hora y al reanudarse si ha vencido el plazo.
- Fallos de consulta: reintentos a los 5, 10, 20 y despues cada 60 minutos.
- Variacion estable de 0 a 60 segundos por equipo; registro del siguiente intento.
- Temporizador independiente del inventario. Un fallo de inventario conserva
  su reintento de 30 minutos y no reinicia el plazo de las actualizaciones.
- Incluye la compatibilidad de 0.20.7 con Activo, Agente instalado y los estados
  de desconexion con cobertura.

Los agentes 0.20.6/0.20.7 siguen usando GitHub latest hasta recibir esta release.
Conservan su espera anterior de 24 horas; reiniciar el servicio fuerza una consulta.
La migracion automatica requiere publicar instalador, manifiesto y firma juntos
como release estable latest. La descarga nueva exige lectura de la version en
RSM mediante el token local del agente; esa lectura real queda por validar.

## Verificacion real y requisito antes de activar la release

El 16/10/2026, la lectura real de la propiedad 1990 mediante el token de agente
de la cuenta del equipo DESKTOP-627V4LK devolvio HTTP 403, tanto con POST como
con GET. Ese mismo token pudo leer el sistema por UUID, su cobertura y su estado
Agente instalado. La lectura de versiones con el token del backend respondio
correctamente: Windows 0.20.6 y Linux 0.4.5.

Antes de publicar como latest: permitir a los tokens de agente leer la propiedad
1990 del registro de versiones ID 1, verificar la consulta con un token real y,
despues de subir todos los assets, cambiar solo la version Windows a 0.20.8 en
RSM. No activar mientras la consulta del agente devuelva 403; no hay fallback a
latest que oculte un error de configuracion. No cambiar Linux en esta entrega.

## Validacion

Pruebas aisladas: seleccion RSM, permisos denegados, indisponibilidad y JSON
invalido; manifiesto/tag distintos; firma y paquetes alterados; reintentos
5/10/20/60, reinicio de la secuencia tras exito, jitter 0-60 segundos, consulta
horaria sin inventario, reanudacion, concurrencia y cancelacion al detener;
fallo del inventario con su reintento de 30 minutos; 28 comprobaciones de
inventarios grandes; 25 comprobaciones de estados/cobertura; redirecciones HTTP
y construccion nativa de URL del instalador. El paquete debe verificarse con
scripts/test-release-package.ps1 contra el binario real y su clave incorporada.

No se han modificado los servicios instalados. Un HTTP 200 con cuerpo vacio al
enviar inventario o version confirma recepcion en cola, no procesamiento final
en RSM. No se promete entrega exactamente una vez ante perdida de respuesta.
La recuperacion del instalador no sustituye una prueba de corte de corriente.

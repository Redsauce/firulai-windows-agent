# Windows agent 0.20.21

Before replacing the installed executable, the installer now stops the service
and waits up to 90 seconds for processes running that exact image to exit and
for an exclusive read/write file probe to succeed. This also covers manual
inventory runs, which are independent of the Windows service. Processes are
never forcibly terminated. A persistent blocker cancels preparation before
installation changes files, with the PID or file error recorded in rs_agent.log.

Recovery uses the same release check before restoring the saved executable,
including restoration when an interrupted installation removed the destination.
Preparation and recovery exceptions are logged instead of silently returning 1.
If preparation times out before replacing any installation file, the unchanged
service is restarted and the unused recovery journal is cleared. It does not
attempt to copy a backup onto the executable that is still occupied.

The check does not reserve the file throughout Inno Setup's installation phase;
a new process or external program can still open it after preparation. Existing
rollback and recovery mechanisms remain necessary. The original process that
blocked Pablo's 0.20.20 installation has not been identified retrospectively.

Validation includes a real child process running the target image, an external
file lock, release after process exit, timeout, missing destination recovery and
non-destructive probing. The release workflow additionally exercises the signed
installer on a fresh disposable GitHub-hosted Windows runner: a persistent
manual process must reject preparation while preserving the old running service,
binary and configuration; a second attempt must wait for that process to exit,
install the signed new agent and clear recovery. Fixtures suppress inventory
collection, disable automatic updates and pin event traffic to loopback.

This candidate retains the 0.20.20 fragmentation and compression protocol and
requires no receiver change. Version 0.20.21 distinguishes the fix from the
already published 0.20.20 and its attempted-version marker. Activation in the
RSM catalog and verification on an actual customer endpoint are separate steps.

# Windows agent 0.20.19

Large inventories use gzip and base64 in a versioned JSON envelope. SHA256 and
the original UTF-8 byte count let the receiver validate the complete inventory
before processing. Small inventories retain the existing JSON format, and
compression is used only when the final envelope is smaller.

Each complete multipart request is limited to 7 MiB, leaving room below the
observed 8 MiB server cutoff. Uncompressed inventories are limited to 64 MiB.
Inventories that remain above the request budget fail explicitly before HTTP;
fragmented uploads are not included in this release.

The existing newServerData event and authentication remain in use. Deploy the
compatible Upload JSON Server data receiver before updating agents. Older agents
remain compatible with that receiver. An HTTP success still means queued, not
that inventory reconciliation or vulnerability analysis has completed.

Validation covers compression round trips, Unicode and metadata preservation,
incompressible data, bounded request sizes, HTTP failures without fallback,
redirects, the updater and C# to Python interoperability using the saved receiver.
